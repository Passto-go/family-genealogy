# 部署常见问题与注意事项

适用于自托管部署：Linux 服务器、Nginx 反向代理、Node.js 24 及以上。文中「应用」指本项目进程，「后台」指 `/admin`。

## 一、部署前置条件

以下五项须全部满足，缺少任一项都会导致启动失败或页面不可用。

| 检查项 | 要求 | 不满足时的表现 |
| --- | --- | --- |
| Node.js 版本 | 24 及以上 | 启动即报错，`node:sqlite` 不存在 |
| 依赖安装 | 已执行 `npm ci` | 报 `Cannot find package` |
| 生产构建 | 已执行 `npm run build`，`dist/` 存在 | 页面返回 404 |
| 会话密钥 | 设置了 `SESSION_SECRET`，长度不少于 32 位 | 进程拒绝启动 |
| 端口占用 | `PORT`（默认 3001）未被占用 | `EADDRINUSE` |

构建与启动必须分离执行。`npm run build` 只生成产物，不启动服务；`npm start` 只启动服务，不执行构建。先构建再启动。

## 二、页面空白或全部 404

**现象**：接口正常，访问首页返回 404，或页面加载后空白。

**原因**：应用同时托管 `dist/` 静态文件，该目录不存在或构建失败时会直接返回 404。

**处理**：

1. 确认项目根目录存在 `dist/index.html`
2. 重新执行 `npm run build`，并检查构建输出是否报错
3. 构建阶段会依次执行审计数据生成与 CSP 哈希校验，任一失败都会中止构建，需按提示修正后再构建

## 三、反向代理与真实 IP

**现象**：登录失败次数限制不生效或误封，或登录后 Cookie 未按 HTTPS 下发。

**原因**：应用只采信 `X-Real-IP` 与 `X-Forwarded-Proto` 两个请求头。反向代理未写入时，所有请求被视为同一来源 IP，限流按同一分桶计算。

**处理**：在 Nginx 中显式设置这两个头，并清除客户端自带的同名头，防止伪造头部绕过限流或影响 Cookie 的 `Secure` 判断。

```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-For "";
```

## 四、HTTPS 证书状态长期为「待签发」

**现象**：后台绑定域名后，证书状态不更新。

**原因**：证书由宿主机脚本签发，签发结果通过状态接口回写。应用未配置 `INTERNAL_API_TOKEN` 时，该组接口返回 403，脚本无法回写。

**处理**：

1. 在应用与证书脚本中配置相同的 `INTERNAL_API_TOKEN`
2. 重启应用与证书脚本
3. 确认脚本可访问应用的状态接口，且反向代理未拦截该路径

证书续期建议由 acme 客户端配合 DNS 接口自动完成，避免依赖 80 端口。

## 五、首次启动与管理员账号

**现象**：访问后台提示「用户名或密码错误」，但不确认密码是否正确。

**原因**：数据库已存在时不会重新初始化，初始密码只在首次建库时生成并打印在启动日志中。

**处理**：

1. 查阅首次启动日志中的初始密码；若曾设置 `INITIAL_ADMIN_PASSWORD`，则以该值为准
2. 无法找回时，执行 `deploy/reset-admin-password.mjs` 重置，命令用法见脚本头部注释
3. 登录后立即修改密码；超级管理员还须绑定 TOTP 验证器，未绑定前后台功能受限

如需恢复为初始示例数据，停止服务后删除 `server/data/family.db`，再次启动即重新建库。该操作会清空全部数据，仅建议在试用环境执行。

## 六、数据备份与恢复

- 全部数据位于 `server/data/family.db` 单文件，使用 WAL 模式
- 直接复制 `family.db` 可能遗漏尚未合并的 `family.db-wal`，得到不一致的快照
- 推荐做法：停止服务后复制 `family.db`、`family.db-wal`、`family.db-shm` 三个文件；或在数据库空闲时执行 SQLite 的在线备份
- 恢复时三个文件一并还原，并保持文件属主与运行用户一致
- 会话密钥位于 `server/data/.session-secret`。生产环境应改用 `SESSION_SECRET` 环境变量，该文件不应随备份分发

## 七、访问控制排查

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 公开族谱不显示在门户列表 | 访问方式为「私密」 | 后台将访问方式改为「公开」 |
| 输入正确口令仍被拒绝 | 管理员已轮换口令，旧口令即时失效 | 向管理员索取新口令 |
| 从公开切回密码访问后，旧口令仍可用 | 切换不会重新生成口令，沿用原口令哈希 | 如需废止旧口令，在后台点「重新生成」 |
| 访客此前已输入口令，切换后无需再次输入 | 访问凭证未过期，且口令指纹未变化 | 正常情况下凭证有效期为 24 小时 |
| 非管理员访问私密族谱显示「不存在」 | 设计行为，避免暴露族谱是否存在 | 无需处理 |

后台切换访问方式时，保存提示会说明是否沿用了原口令。若提示为「沿用原访问口令」，说明本次未生成新口令。

## 八、常见报错对照

| 报错信息 | 原因 | 处理 |
| --- | --- | --- |
| `Cannot find module './shared.js'` | `server/repo/shared.ts` 未提交或未部署 | `git add server/repo/shared.ts` 后重新提交、构建 |
| `EADDRINUSE :3001` | 端口被其他进程占用 | 停止占用进程，或通过 `PORT` 指定其他端口 |
| `SESSION_SECRET 未配置或强度不足` | 生产环境缺少密钥，或使用了占位符 | 生成至少 32 位随机串并注入环境变量 |
| `SQLITE_CANTOPEN` | 数据目录不存在或无写入权限 | 创建 `server/data/` 并赋予运行用户读写权限 |
| 构建中止并提示 `CSP 哈希与 index.html 内联脚本不一致` | 内联主题脚本被修改，哈希未同步 | 按输出提示更新 `server/app.ts` 中 `script-src` 的 sha256 值 |
| 首屏主题闪烁，控制台出现 CSP 违规 | 同上，但发生在已有部署上 | 重新构建并部署；不要通过放开 `unsafe-inline` 规避 |

## 九、升级注意事项

1. 先备份数据库
2. 拉取代码后执行 `npm ci`，确保依赖与锁文件一致
3. 执行 `npm run build`，构建失败时不要覆盖正在运行的产物
4. 重启进程，并检查 `/api/health` 返回 `{"ok":true}`
5. 若涉及数据库结构变更，启动时会自动迁移；迁移前请确认备份可用
