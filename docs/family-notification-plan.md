# 家族通知消息（二期）

本文件记录「家族通知消息」功能的需求定义，用于二期开发。当前版本**不包含**该功能，代码中不存在相关实现。

## 一、定位

家族通知是**单向信息展示**：由管理员在后台发布，族人进入具体家族页面时看到。系统不提供回复、点赞、评价入口，也不记录任何以用户为单位的接收或阅读状态。

- 与「信息反馈」的区别：信息反馈由访客提交、管理员审核，方向相反且需要处理流程；家族通知由管理员发布、访客只读，无处理流程。
- 与「站点设置」的区别：站点设置面向所有家族统一生效；家族通知按家族独立维护，只在对应家族内出现。

## 二、需求条目

### N1 触发范围

- 仅在具体家族页面（`/t/<slug>`）加载完成后判断并展示。
- 总目页、首页、家族文献、法务页与后台页面不展示家族通知。
- 家族未发布、访问口令校验未通过时不展示。

### N2 展示条件

同时满足以下条件的通知才展示：

- 状态为「已发布」；
- 当前时间在生效区间内（起始时间已到，结束时间未到；结束时间为空视为长期有效）；
- 未被手动下线。

符合条件的通知为 0 条时不出现浮层，页面不产生额外占位或空白。

### N3 展示形式

- 网页浮窗，覆盖在页面内容之上，不改变页面布局。
- 多条通知合并为一个浮窗，按置顶优先、发布时间倒序排列，内容超出时浮窗内部滚动。
- 桌面端位于视口右下角；移动端为底部卡片，宽度不超出视口并保留安全边距。
- 浮窗包含标题、正文、发布时间（可选）与关闭按钮。

### N4 关闭行为

- 用户可随时主动关闭，浮窗立即消失，不阻塞页面其余操作。
- 关闭状态保存在浏览器本地，键值包含家族标识与通知标识，按通知的配置生效：
  - 「每次进入都提示」：关闭仅在本次会话内有效；
  - 「关闭后 N 天不再提示」：N 天内不再展示该条通知。
- 通知内容经后台编辑并重新发布后视为新通知，需重新提示。
- 用户清除浏览器数据后重新提示，属于预期行为。

### N5 单向性约束（硬性）

- 不提供任何回传通道：无「收到」「确认」「已读」按钮，无回复框，无表情或评分。
- 服务端不落库任何与具体用户关联的展示、点击或关闭记录。
- 不统计阅读量、点击率等以用户为维度的指标；如需运维数据，只允许不含账号与设备标识的汇总请求计数。
- 不发送短信、邮件、微信模板消息等站外推送。

### N6 内容与格式

- 正文为纯文本，保留换行；不解析 HTML，不执行脚本。
- 正文可包含站内链接与白名单域名的外链，渲染时统一附加 `rel="noopener noreferrer"`。
- 单条正文长度上限建议 500 字，超出时后台提示并禁止保存。
- 支持置顶、生效起止时间与手动下线。

### N7 发布权限

- 家族管理员可维护本家族的通知；超级管理员可维护任意家族的通知。
- 普通管理员只读，不能新增、编辑或下线，与既有权限边界保持一致。
- 发布、编辑、下线写入操作日志，记录操作者、时间、家族与通知标识；日志追加后不可修改或删除。

### N8 后台管理

- 入口位于后台家族相关页面，按家族维度列出通知。
- 列表字段：标题、状态、置顶、生效区间、更新人、更新时间。
- 操作：新增、编辑、发布、下线、删除。

## 三、明确不做

- 消息回执、已读状态、用户回复与讨论区；
- 站外推送（短信、邮件、微信模板消息）；
- 按用户特征定向投放；
- 阅读统计报表；
- 访客自行发布或转发通知。

## 四、内容来源与合规约束

通知只由站内管理员录入、不接受访客投稿，因此它属于运营方自行发布的信息，而非用户生成内容。设计上固定以下约束：

- **来源限定**：仅已登录且通过权限校验的管理员可写入，接口侧不提供匿名写入路径；
- **发布前审核**：新增与编辑先保存为草稿，需再次确认后才对前台生效；对外表述较重的通知建议由站点运营者本人复核；
- **可即时撤回**：任意通知可一键下线，下线后前台立即不再展示；
- **留痕可追溯**：发布内容、操作者与时间写入操作日志，日志只追加不删除，便于事后核查；
- **与法务文本一致**：隐私说明需补充「通知仅用于家族内信息告知，不收集接收行为」的表述，避免实际行为与声明不一致。

## 五、验收标准

1. 家族无有效通知时，前台无浮层、无空白占位；
2. 存在多条有效通知时，单浮窗合并展示，顺序符合置顶与发布时间规则；
3. 关闭后按配置周期不再提示，刷新页面与更换设备表现一致；
4. 通知下线或超出结束时间后，前台立即不再展示；
5. 前台代码中不存在上报关闭或阅读行为的请求；
6. 家族管理员不能操作其他家族的通知，普通管理员无写入权限；
7. 发布与下线操作均可在操作日志中检索到。
